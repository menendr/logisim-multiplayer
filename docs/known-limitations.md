# Known limitations

This is a functional MVP prototype, not a claim of full production validation or every original tool being synchronized.

- Only built-in components/default circuit appearances participate. External libraries, appearance editing, ROM contents editor, project options, toolbar/mouse mappings, circuit ordering and other unrecognized action classes are unavailable in collaborative mode. Circuit create/rename/remove and main selection are supported. Original offline tools remain available.
- The ROM listener in 2.7.1 reports a change after it already modifies the contents. Its collaboration guard explicitly invokes the original inverse before denying it. Other candidate errors reconcile to accepted state. There is no local offline queue.
- One unacknowledged transaction per client; rapid subsequent edit gestures are denied with a synchronization status/beep until acceptance. The two clients can submit concurrently. Safe per-client undo/redo is now implemented, with partner-touch invalidation and full model checks. History is capped at 100 entries / 4 MB and belongs to the saved server/name profile; older pre-update edits have no reconstructed history. Validation and durability are synchronous on the server, so latency grows with project size and disk speed.
- Names, overlapping identical components and resource/history limits are documented in README/protocol. A local session must be exported/recreated at the history cap. There is one server project, no invite-based access control, and no online project replacement/deletion API.
- Input values, simulator state, ticks, viewports, tool defaults and selections are local. Changes to affected components can reset simulation state. Initial/recovery snapshots reset local simulation. Remote deletion can clear affected selections; remote attribute replacement uses Logisim replacement maps.
- Local file exports can include a provisional edit while it awaits acceptance; the menu explicitly shows Synchronizing. Wait for Connected and synchronized before exporting a server-accepted copy.
- Accepted work is durable. After a desktop process crash, operations that did not reach the server need to be repeated. In-memory uncertain operations can be retried idempotently after connection loss; Reconnect needs only the server address and name; no invite is used.
- Latest-generation corruption deliberately makes recovery read-only. Review backups and create a new session from a reviewed export. Failed/partial generations are preserved, not silently promoted.
- Existing project options/toolbars are not part of the collaborative document; each desktop retains its own options across join/recovery. Server backups use default options. Preserve local exports when these settings matter.
- Earlier Linux reconnect tests exposed a missing-response stall. Failed sockets are now forcibly closed and a seven-second synchronization deadline restarts stalled synchronization. Final suites passed with the first join response deliberately omitted; see test-results.md.
- No public WSS/reverse-proxy, WAN latency/load, power-loss, macOS desktop or Linux graphical desktop validation has been claimed. Windows desktop and Linux headless Java behavior are the tested environments. JDK 25 reports existing deprecation warnings in the original source.

- Release packaging audit: exact historical source/license matching for the unchanged JavaHelp 2.0_03 and MRJAdapter binaries remains unresolved. See THIRD_PARTY.md. This working local prototype is not represented as a fully cleared redistribution release.
